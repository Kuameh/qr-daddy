QR Daddy design system v1.3

A calm tool with a loud voice. The generator is neutral and precise; personality lives in the heavy display type, hard ink shadows on stickers and the primary action, and the codes themselves. Cobalt is the only accent. Mirrors DESIGN_SYSTEM.md. Designs: Brilliant project qr-daddy, canvases “QR Daddy — Final” and “QR Daddy — Account”.

Product rule. Making and downloading a static code never needs an account. Only turning on Dynamic asks for one, and it explains the benefit (change where the code points after printing, see its scans) instead of blocking. Signing in is a benefit, never a gate.

1. Design tokens

Colour

Each swatch shows light on the left, dark on the right. Dark follows the system setting, and so does this page. Ink flips to a light grey, so ink borders and hard shadows become light edges on a dark page. Stickers keep their light colours (white face, ink edge) so codes stay dark on white. on-accent is white in both, for text on cobalt.

Dark contrast: ink on surface 14.5:1, ink-soft 8.3:1, muted 6.1:1, danger 6.2:1, warning 8.3:1, white on accent 5.9:1, on-danger (#131315) on danger (#FF6B7D) 6.8:1. Light: white on danger 5.9:1. on-danger turns dark in dark mode because white on the light dark-mode red fails contrast.

6. Implementation notes

No hex literals or arbitrary values in components; add a token first, with a dark value. Touch targets 44px, inputs 16px on phones. Error copy says what happened, then what to do. Route handlers answer { message, details? } in plain copy and the client shows both. Chart bar heights and meter widths may be inline styles (data-driven).
